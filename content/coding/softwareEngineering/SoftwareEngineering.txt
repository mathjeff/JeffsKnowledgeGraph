What is automation?

  Automation is the process of creating a system to do something on its own that would otherwise be done by a person.

How can I decide what to automate?

  Tasks that are valuable to automate are tasks whose net present value of their benefits are higher than their costs.

  If you want to know whether to automate a particular task, you should be reasonably confident about the costs and benefits, along with other things you could be doing instead.

  You should also incorporate potential risks of automating a task incorrectly: what's the cost of a potential bug in an automation solution?

How can I estimate the benefit of automating?

  The benefit of automation is to not have to do a certain task manually in the future.

  One simple way to estimate the cost of doing a task in the future is to assume that it will remain similar to the cost in the present. For example, if you have repeatedly spent an average of 10 minutes every day on a specific task in the past, it may be reasonable to suppose that if nothing changes, you will spend an average of 10 minutes every day on this task in the future.

  As a result, if a task is a little bit inconvenient to do manually and is more effort to automate, it is often worthwhile to do the task manually several times to get an estimate of the cost of not automating it, before spending the larger effort required to automate it.

  Determining the cost of repeatedly doing a task manually can be difficult if the cost is spread out among several people. This means that learning what is inconvenient for others to do makes it easier to know what to improve.

  There are several ways to learn what tasks are difficult for other people, including:

  * Asking people if they have any complaints

  * Surveying people about specific concerns

  * Modifying the tool that they use to measure any inconveniences, such as time spent

  * Modifying the tool to make it easy for users to complain when they are using it

  If the task is difficult, boring, and important, then in addition to saving time, automation might also improve accuracy, by being more reliable than a human.

What is a software dependency?

  A dependency in software is the idea that one entity uses something else.

  This allows the second entity to reuse what has already been provided by the first entity.

  For example, in the renderer for this knowledge graph, we use Marked to help generate appropriately styled html more easily

Dependencies aren't free

  Dependencies can have security issues

  Dependencies can increase the size of the final product (requiring more bytes to download and store)

  Dependencies can be complicated projects, and if their maintainers aren't interested in adding a new feature, they can be more difficult to change

  As a result, if a dependency only provides a small amount of value to your project, it is often worthwhile to reimplement that small amount of logic yourself.

Avoid duplicate code

  Code duplication is the idea of having multiple pieces of code that do the same thing.

  This is usually a bad thing because if you want to change the logic, you have to remember to change each copy.

  If you forget to change every copy, the improvement that you were adding might not be applied to the unmodified copies.

  If you are writing the same code multiple times, you usually should put the code in one place and reuse it.

  If several people or projects are reusing the same code, it's often helpful to move the code into another location and then specify a dependency so you can reuse it.

What is unit testing?

  Unit testing is a way of verifying part of a computer system. A unit test is the smallest class of test. A good unit test only does in-memory operations and doesn't need to access the filesystem or the network.

 - What is a computer program?

What is integration testing?

  Integration tests are automated tests that interact with a running instance of a computer system to make sure it is working correctly.

  Integration tests run more slowly than unit tests.

  Also, integration test failures provide less detail about the location of the problem than unit test failures do.

  So, integration tests should be focused on checking things that are difficult to check with a unit test.

 - What is a computer program?

Continuous integration

  Continuous integration is the idea of having a system that verifies that software builds correctly and passes tests

  This can be helpful because as software grows, the number of ways to use it can grow too, and it can be easy to forget to verify all of the combinations.

People make mistakes

  So, we try to set up systems to prevent the most common and most important mistakes

Rushing can increase mistakes

  When someone is in a hurry to complete a task, it is often more likely to make a mistake than when taking the time to be more careful.

  If you would like to see this for yourself, you can consider completing some tasks quickly and some tasks more carefully and comparing the results of each.

  * You may find that an easy way to get a sense of urgency is to do an efficiency experiment in [ActivityRecommender](https://github.com/mathjeff/ActivityRecommender)

  An advantage of rushing is that relevant work can get done more quickly.

  In cases where mistakes are more costly it often helps to be more careful, and in cases where mistakes are more harmless it often helps to be efficient.

 - People make mistakes

Mistakes in large systems

  In a large enough system, mistakes will happen fairly often.

  * If we can automatically detect a mistake and can prevent causing a problem for anyone else, that is usually the best outcome.

  * If we can't prevent a mistake but we can quickly detect a problem

      * That gives us more time to handle it before it causes much trouble

      * That gives us more information about what triggered the problem

          * That gives us more information about how to fix it

  * If we can make it easy to undo the mistake, that can also be helpful

      * It can help to make backups of information that is important

          * If one copy of a piece of information is lost, if there is a backup, it can be restored from the backup

  If you're interested in a simulation of a large system with lots of opportunities for mistakes, you might be interested in [Oxygen Not Included](https://store.steampowered.com/app/457140/Oxygen_Not_Included/) or [Factorio](https://www.factorio.com/).

Protecting against data loss

  There are several types of problems that can cause data to be unavailable:
  * Someone can accidentally delete their own file
  * Someone can accidentally delete someone else's file
  * Someone can intentionally delete someone else's file
  * A drive can get damaged
  * A drive can get old and wear out
  * The system can be so old that we no longer know how to read it

  There are a few ways we can guard against data loss

  * Having a backup of information can allow us to restore it if there is a problem that doesn't also affect the backup
      * The safest backup strategy is usually to have a backup on some other system using different credentials
          * A different system is least likely to be affected by one of these problems at the same time as the original
          * There are websites that will store data for you
              * GitHub can store code and smaller files, for example
      * Making backups to another drive on the same system is another strategy
      * Making backups to another part of the same drive is another strategy
  * Setting file permissions can prevent people from modifying the file with software
      * You can even set the permissions to prevent yourself from simply modifying the file
      * This doesn't protect against drive failure

Recovering from data loss

  Ways to potentially restore files that have been deleted:

  * Copy from a backup
      * This is usually the easiest and safest way, but requires that you made a backup beforehand
  * Regenerate the files
      * If you recorded how the files were made, then you may be able to run the same process again
      * If you remember approximately how the files were made, then you might be able to approximately make them again
  * Attempt to search the drive for files that haven't been deleted yet
      * When a drive deletes a file, it usually marks the file's location as available but doesn't delete it yet
      * If the file hasn't been overwritten yet, then there's a chance it may still be recoverable
      * You can try `testdisk` explained at https://itsfoss.com/recover-deleted-files-linux/

Issue trackers

  An issue tracker is a system that helps people to remember work that needs to be done, by allowing a user to do this:

  * Write down tasks that need to be completed
  * Search for tasks that haven't been completed yet
  * Record that a specific task is now complete

  Some issue trackers also include other features, including:
  * Allowing users to directly specify the importance of a task
  * Allowing users to vote in favor of raising the importance of a task
  * Allowing users to specify that one task needs to wait for something else before it can be worked on

  Some popular issue trackers:
  * [Jira](https://www.atlassian.com/software/jira)
  * [GitHub Issues](https://github.com/features/issues)

What is Conda?

  [Conda](https://github.com/conda/conda) is a tool that makes it easy to create independent environments that each have their own tools and their own versions of dependencies.

  Since these environments are independent, updating the version of a dependency in one environment doesn't need to also update the version of that dependency in another environment. This reduces the number of opportunities for version conflicts, in case two tools each require a different version of a third tool.

How do I create a Conda environment?

  You can [create a Conda environment](https://docs.conda.io/projects/conda/en/latest/user-guide/tasks/manage-environments.html#creating-an-environment-with-commands) via `conda create`

  For example, to create a Conda environment named "sample" having Jupyter Notebook in it, you can do this:

  ```
  conda create -n sample jupyterlab
  ```

 - What is Conda?

How do I add a local tool to Conda?

  1. [Create a meta.yaml file](https://docs.conda.io/projects/conda-build/en/latest/resources/define-metadata.html) explaining how to run this tool
  2. Run `conda build` (see [here](https://docs.conda.io/projects/conda-build/en/latest/resources/commands/conda-build.html) ) to ask Conda to create a package for it

How do I use a Conda tool that I just built locally?

  When you ask Conda to create a package, Conda puts the package in a directory containing a `repodata.json` file. This directory represents a Conda channel, so you can just specify its directory after the `-c` option.

  For example, to create an environment named "sample-environment" using the tool named "mytool" using the channel represented by the working directory, do this:

  `conda create -n sample-environment -c ./ mytool`

What is a dependency graph?

  A dependency graph is a network, where each node represents a task or action, and each edge represents that one action must wait for the other one.

  For example, you could describe the process of making bread with a dependency graph like this:

  * You need to get flour (node)
  * You need to get yeast (node)
  * You need to get water (node)
  * You need to get salt (node)
  * You need to combine these ingredients into bread (node)
    * This depends on getting the flour (edge)
    * This depends on getting the yeast (edge)
    * This depends on getting the water (edge)
    * This depends on getting the salt (edge)

Evaluating a dependency graph in software

  If you have a collection of specific computer tasks, you can make it easy to run them all by describing them with a dependency graph and passing them to a program that can evaluate dependency graphs.

  Programs that execute dependency graphs are often referred to as [build tools](https://en.wikipedia.org/wiki/Software_build), because a common use case for these programs is to build other software.

  These programs often provide various features for evaluating these graphs more quickly or conveniently, including parallelism (doing multiple things at one time) and incrementalism (skipping things that are already done).

  An older example of a tool for evaluating dependency graphs is [Make](https://www.gnu.org/software/make/).

  A more recent tool for evaluating dependency graphs is [Gradle](https://gradle.org/). It also provides various plugins for some popular use cases, particularly building Java projects.

  If you just want a graph executor and don't want any help describing the task graph, you can consider [ninja](https://ninja-build.org/).
