# Information about Version Control

What is a version control system?

  A version control system is a system that keeps track of the history of a collection of files, and allows inspecting and labelling changes along with undoing and redoing named changes.

Benefits of version control

  A version control system can be helpful in these cases:

  * A version control system can allow you to compare two versions to see what changed
      * This can be helpful if something stopped working and you want to see what might explain it
      * This can be helpful when doing code review so you can see what changed between two versions
  * A version control system can allow you to restore a previous version
      * This can be helpful if something stopped working and you want to return to the previous version
  * A version control system can allow you to merge your changes with another person's changes
      * This can help multiple people to work on the same project at the same time without overwriting each other's changes
  * A version control system can allow you to easily undo a set of related changes all at once
      * This can be helpful if you discover that there was a problem with just that set of changes and you don't want to undo all of the changes that happened since then
  * A version control system can allow you to easily set aside your changes for later
      * This can be helpful if your changes are not done yet but you found something else you want to work on first

What is a merge conflict?

  A [merge conflict](https://stackoverflow.com/questions/24852116/what-exactly-is-a-merge-conflict) is when two different people make different changes to the same part of a file, and someone is trying to apply both of these changes at once.

What is a mergetool?

  A mergetool is a tool that Git runs to help you resolve merge conflicts.

How can I enable vimdiff as the default mergetool in Git?

  As described [here](https://gist.github.com/karenyyng/f19ff75c60f18b4b8149), run this:

  ```
  git confit --global merge.tool vimdiff
  git config merge.conflictstyle diff3
  ```

  * To insert text, type "i" and type some text and press <Escape>

How can I resolve merge conflicts without a mergetool?

  To resolve a merge conflict without a mergetool, you can edit the files directly.
  Run `git status` to see the files that need changing.
  Use your favorite editor to edit them.
  Use `git add <filename>` to tell git when you are done editing a file.

How can I restore state from a git commit?

  Each git commit has a set of files and some history.

  Your git repository also has a HEAD pointer, some files, and usually a current branch

  * If you want to update the commit that the current branch points to:
      * If you want to update your files too, run `git reset <otherCommit> --hard`
          * Careful - this will overwrite any uncommitted changes you have and can be dangerous
      * If you don't want to update your files, run `git reset <otherCommit>`
  * If you don't want to update the commit that the current branch points to:
      * If you want to update the HEAD pointer and your current files, run `git checkout <otherCommit>`
      * If you don't want to update the HEAD pointer:
          * If you want to update all your files, do `git checkout <otherCommit> -- .`
              * This will also overwrite any changes
          * If you want to update some of your files, do `git chekout <otherCommit> -- <subdirectory>`

What is git reflog?

  Git's reflog is a history of commits that you have checked out. Run `git reflog` to see it.

  This will output a history of:

  * The hash of the commit
  * The names of any branches pointing at this commit
  * A description of which git commit brought you to that commit

How do I restore changes from the reflog?

  After you get a history of changes from `git reflog`, you can get them back like any other commit.

How can I resolve a merge conflict?

  If you would like to see all of the versions of the file (common ancestor, left version, right version, and merge version) at once and would like to use `vim`, tell `git` to use `vimdiff` as a mergetool.

  If you would like to edit the file with another program, you don't need to configure a mergetool.

  When you think you have resolved all of the conflicts, make sure to check that your changes look right (`git status` and `git log -p`)

  If you make a mistake, you can go back to old versions of files or commits using the reflog

  When you are sure you have resolved all of the conflicts, tell Git that you are done by rerunning the command that caused the conflict: either `git rebase --continue` or `git merge --continue`

What is code review?

  Code review is the process of having a person look at code you've written to check for problems.

  Code review is done before the code is submitted, usually.

  If a code reviewer finds a problem, they usually write a comment on the change, which can often be located on a certain line of a certain file.

Why do code review?

  * Code review can reduce issues in the near future
    * Code review can prevent bugs from being submitted into the system
    * Code review can prevent performance issues from being submitted into the system
  * Code review can improve quality later
    * Reviewers can share things that they have learned that are relevant to the code
    * Reviewers can learn things from code that they are reviewing

 - What is code review?

How can I get somebody else's change on my computer?

  Getting somebody else's change on your computer requires choosing whether you want to:

  * Get the exact file state that that person's change describes, including all of the history
      * If this is what you want, then you want to check out that person's changes
  * Apply that person's change on top of your changes
      * This keeps that person's change and discards history before it
      * If this is what you want, then you want to cherry-pick that person's changes
  * Combine that person's change with your changes
      * This preserves any changes before that other person's changes
      * This preserves any changes before any of your own changes
      * If this is what you want, then you want to merge that person's changes
